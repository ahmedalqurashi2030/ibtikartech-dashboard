# عقد تصميم الواجهة العامة الحالي

هذا المستند يصف القيم والعقود الموجودة فعليًا في واجهة `public_preview` على
الفرع `main`. لا يقدّم Design System بديلًا، ولا يمنح إذنًا لتغيير المحتوى أو
الباك إند.

## مصدر الحقيقة

- التجربة العامة النشطة هي `templates/public_preview/` و`static/public_preview/`.
- `templates/public_preview/base.html` يملك document shell العام.
- `header.html` و`mobile_menu.html` و`footer.html` و`runtime.html` مكونات عامة.
- صفحات الخدمات العامة الست تُعرض من `apps/services/public_views.py` بقوالب
  صريحة داخل `public_preview/pages/`، ولا تستخدم حاليًا قالب الكتالوج الديناميكي
  `templates/services/detail.html`.
- صفحات تفاصيل خدمات التجارة الست ترث
  `public_preview/families/service_detail_base.html`، وصفحات فئات الحلول الخمس
  ترث `public_preview/families/service_category_base.html`. صفحات المقالات
  الثلاث ترث `public_preview/families/article_detail_base.html`، بينما يبقى
  فهرس المعرفة `knowledge.html` صفحة مستقلة لاختلاف رحلة التصفح والتصفية.
  تملك العائلات الغلاف والأصول المتطابقة فقط، وتبقى الأقسام السردية وSEO
  والمحتوى داخل الصفحة المالكة.
- لا تُدمج منظومتا العرض ولا تُحذف القوالب غير النشطة قبل تدقيق المسارات
  والمراجع واتخاذ قرار معماري مستقل.

## السلوك العام

- يوجد Skip link إلى `#main-content`.
- `:focus-visible` مملوك لـ`base.css`.
- `prefers-reduced-motion` يعطّل الحركة الانتقالية الطويلة.
- الحاوية تستخدم `margin-inline`، ما يحافظ على RTL/LTR.
- Header وMega Menu وقائمة الجوال مملوكة لـ`ibtikar-shell.css` و
  `ibtikar-shell.js`.
- هوية الصفحة تمر عبر `body[data-page]`، وهو العقد المعتمد لسلوك JavaScript.
- روابط الصفحات الداخلية يجب أن تستخدم Django named URLs.

## طبقات CSS الحالية

الطبقات القانونية الموجودة الآن هي:

1. `tokens.css`: القيم الأساسية والدلالية.
2. `base.css`: reset، الحاويات، الوصول، الإيقاع العام.
3. `components.css`: الأزرار، CTA، البطاقات وعناصر الواجهة المشتركة.
4. `ibtikar-shell.css`: Header وNavigation وMega Menu وMobile Menu وFooter.
5. `pages/*.css`: عائلات وصفحات وتجارب متخصصة.
6. `foundation/typography-system.css`: ضبط الطباعة النهائي الحالي.

حدود التحميل أصبحت صريحة: `base.html` يحتفظ فقط بالتحسينات المشتركة فعليًا
مثل Mobile Action Pairs ونظام الطباعة. أما تحسينات الصفحة الرئيسية وتخطيط صفحات
الخدمات وبطاقات الخدمات المرتبطة فتُحمّل بنظام opt-in حسب
`apps/public_preview/asset_contract.py`. لا تُحذف طبقات refinement أو نسخ
`dashboard/` قبل إثبات مراجعها وتحديث اختبارات mirror/ownership.

## عقد المكونات المستهدف

يُصنّف كل جزء قبل استخراجه:

| التصنيف | متى يستخدم | مثال |
| --- | --- | --- |
| Primitive | وظيفة ودلالة واحدة مستقرة | Button، Breadcrumb item، Section heading |
| Pattern | تركيب متكرر له سلوك أو معنى واضح | CTA card، Gallery، Decision tabs |
| Page family | نفس رحلة الصفحة وترتيبها مع اختلاف المحتوى | تفاصيل الخدمات، المقالات |
| Page-owned | سرد أو تجربة فريدة لا تتكرر وظيفيًا | الرئيسية، ثراء |

قواعد القرار:

- تطابق الوظيفة والبنية والسلوك في 3 صفحات أو أكثر يسمح بالاستخراج.
- التشابه البصري وحده لا يكفي؛ عند اختلاف الدلالة نشارك CSS فقط.
- الاختلافات المضبوطة تُعبّر عنها variants محدودة، لا شروط متشعبة.
- إذا احتاج المكوّن معاملات كثيرة أو شروطًا حسب اسم الصفحة، فمستواه خاطئ.
- لا يُنقل المحتوى إلى Wagtail blocks قبل استقرار عقد العرض والتحرير.

## عقد كل مكوّن جديد

يجب توثيق: الغرض، المدخلات المطلوبة والاختيارية، variants، HTML الدلالي،
keyboard/focus، RTL، responsive، حالات empty/error عند الحاجة، مالك CSS، مالك
JavaScript، analytics attributes، وحالات reduced motion.

## سياسة تحميل الأصول المستهدفة

- `base.html` يحمل الأصول العامة فعلًا فقط.
- كل عائلة صفحات تملك CSS/JS واحدًا قانونيًا عند الحاجة.
- لا يُحمّل ملف خاص بالرئيسية أو الخدمات على صفحات لا تستخدمه.
- لكل سلوك JavaScript مالك واحد وتهيئة idempotent مبنية على `data-*`.
- لا يُضاف Framework أو مكتبة حركة جديدة لمعالجة مشكلة تنظيمية.

## حدود المرحلة الحالية

هذه الوثيقة لا تغيّر التصميم أو القوالب. أي ترحيل لعائلة صفحات يجب أن يحدث في
فرع مستقل، يبدأ بمقارنة مرجعية، ويحدّث اختبارات العقد وأدوات التحويل وGitHub
Actions معًا حتى لا يصبح النظام الجديد استثناءً غير محمي.
