# عقد ملكية المحتوى العام

## القرار الحالي

المستودع `ibtikartech-dashboard` يظل المصدر الوحيد للواجهة العامة، لكن ملكية
**المحتوى** أصبحت معلنة على مستوى نوع الصفحة بدل اعتبار كل الصفحات ثابتة.

| المجال | المالك |
| --- | --- |
| الهوية والشعار والتذييل | Wagtail `SiteSettings` |
| التواصل والسوشيال | Wagtail `SiteSettings` |
| SEO الافتراضي والتحقق | Wagtail `SiteSettings` |
| معرّفات القياس الخارجية | Wagtail `TrackingSettings` مع بوابة البيئة |
| صفحة المقالات `/knowledge/` | Wagtail `ArticleIndexPage` |
| صفحات المقالات `/knowledge/<slug>/` | Wagtail `ArticlePage` |
| بقية نصوص وأقسام الصفحات العامة | Django templates |
| طلبات المشاريع | `PublicInquiryForm` ثم CRM/Sales models |

## Cutover المقالات

المقالات هي أول نطاق تحريري تم نقله فعليًا إلى Wagtail، بما يتوافق مع ADR-009
وADR-010. المسارات العامة بقيت نظيفة وثابتة، بينما أصبحت بيانات المقال ومحتواه
ومعلومات البطاقة وSEO وحالة النشر تُدار من `/control/`.

تم ترحيل المقالات الستة المنشورة إلى Snapshot ثابت داخل migration ثم إلى
`ArticlePage`. القوالب القديمة باقية مؤقتًا كمرجع عرض/rollback فقط وليست
مصدر المحتوى المنشور.

المقال الجديد يُنشأ كابن لصفحة المقالات، ويظهر تلقائيًا في القائمة والمسار العام
والـsitemap بعد نشره. المسودة أو الصفحة غير العامة لا تظهر للزائر.

## ما لم يتغير

الرئيسية، صفحات الخدمات، ثراء، عنّا، التواصل وبقية الواجهة لا ترتبط حاليًا
بحقول Wagtail Page. أي توسيع لاحق يمر بنفس البوابات التالية:

1. خريطة مصدر على مستوى الحقول.
2. ترحيل محتوى قابل للتكرار وخطة rollback.
3. تطابق SEO وstructured data والروابط.
4. Preview وpublishing workflow وصلاحيات واضحة.
5. مصدر محتوى واحد لكل مسار بلا fallback صامت.
6. اختبارات rendering وvisual regression قبل الدمج.
