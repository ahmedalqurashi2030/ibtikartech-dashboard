# سجل أصول وتجربة صفحات الخدمات — 2026-09-01

هذا السجل يحدد ملكية الأصول المشتركة بعد تحسين رحلة صفحات الخدمات محليًا. المرجع التنفيذي هو `service-pages-experience-execution-plan-v2.md`، بينما يبقى محتوى كل خدمة مملوكًا لقالبها.

## استثناء صفحة تحسين المنتج

تحتفظ `product-page-optimization.html` بتصميمها المخصص. ويملك:

- `source-product-page.js` نقاط الشرح الخاصة بالصفحة وشريط CTA للجوال فقط.
- `product-page-accessibility.css` حواجز الوصول المتخصصة: 44px للنقاط، حالة الاختيار، المساحة الآمنة، وتقليل الحركة.
- `commerce-service-detail.js` يظل مالك معرض الصور وتبويبات القرار؛ لا يعاد تنفيذها في ملف الصفحة.

## قواعد الملكية

- لا يحمل `base.html` أصولًا تخص مسارًا واحدًا.
- لا يعاد تحميل `tokens.css` داخل صفحات فرعية عندما يكون block القاعدة فعالًا؛
  صفحة المنتج تعلن الأصل مرة واحدة لأنها تستبدل block الأصول كاملًا.
- لا يوجد مالكان للسلوك نفسه؛ عقد الملكية مفحوص عبر `apps/public_preview/asset_contract.py`.
- محتوى النطاق والمتطلبات والمدة والأسئلة والوعود يبقى داخل قالب الخدمة، ولا ينقل إلى JavaScript.
- أي CTA يطلب عرضًا يرسل `goal/service` و`source` ويعلن حدث `quote_request`، بينما نجاح الاستفسار لا يسجل إلا بعد نجاح النموذج.

## التحقق المحلي

- `pytest`: ‏242 اختبارًا ناجحًا، بلا فشل.
- فحص Django ومخطط migrations دون تغييرات، و`pip check` دون تعارضات.
- عقد القوالب وعقد ملكية الأصول.
- اختبارات أساس UX الثابتة.
- فحص فعلي في المتصفح بعروض 375 و768 و1024 و1440 للصفحات الست، مع RTL
  وعدم وجود overflow أو صور أساسية مكسورة أو IDs مكررة أو أخطاء console.
- تحقق تفاعلي من التبويبات وFAQ وHotspots وEscape/focus وشريط CTA للجوال.
